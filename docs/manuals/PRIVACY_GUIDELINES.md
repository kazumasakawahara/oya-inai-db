# プライバシーガイドライン & 個人情報保護運用規程

---

## 1. はじめに

親亡き後支援データベース（oya-inai-db）は、知的障害・精神障害のある方の支援情報を管理するシステムです。扱うデータには**要配慮個人情報**（障害の種類・等級、医療情報、生育歴等）が多く含まれるため、個人情報保護法および関連ガイドラインに準拠した運用が必要です。

本ガイドラインは、本システムを導入する事業所が、個人情報保護規程を整備する際の参考資料として作成されたものです。各事業所の既存規程と照らし合わせ、必要に応じてカスタマイズしてください。

## 2. データの保管場所と流れ

### 2.1 データの保管

本システムのデータ本体（Neo4j グラフDB）は**ローカル環境**（利用者のパソコン内の Docker コンテナ）に保管されます。操作画面（Web画面）と API サーバーも同じパソコンの中で動きます。

```
[パソコン内]
├── Web画面 (Next.js, port 3001)   ← ブラウザで開く操作画面
├── API サーバー (FastAPI, port 8001)
├── Neo4j コンテナ (port 7687 / 7474) ← 障害福祉データ
└── neo4j_data/ ← 永続化ボリューム
```

> **重要（AI機能を使う場合のみ外部送信あり）**: 台帳の閲覧・登録、緊急照会、期限アラートといった中核機能は、**外部に一切データを送らずローカルだけで完結**します。一方、AI 機能（意味検索・AIチャット・ナラティブ抽出）を使う場合は、選んだ AI の提供元サーバーへデータが送信されます。詳細は 2.2 と 2.3 を必ず読んでください。
>
> **音声の文字起こしは 2026-08-12 に廃止しました。**また、AI を Claude 一本にまとめる方針のため、意味検索も廃止予定で、「AI なしで中核機能だけを使う」形も取りやめます（→ COMPLETE_MANUAL.md 2-3）。

### 2.2 外部AIとデータの扱い（重要）

本システムで使える AI は 3 種類あり、**どれを選ぶかでデータの行き先が変わります**。設定は `.env` ファイルまたは Web画面の「LLM設定」で行います。**どれも設定しなくてもシステムはエラーにならず、AI 機能だけがスキップされます。**

| 選択肢 | データの行き先 | 費用 | 実在の個人情報を扱う運用での可否 |
|---|---|---|---|
| **Ollama**（ローカル実行） | **外に出ない**（パソコン内で完結） | ¥0 | ✅ 推奨 |
| **Gemini 有料枠**（課金を有効にした API キー） | Google のサーバー。**Google のプロダクト改善には利用されない** | 従量課金 | ✅ 可 |
| **Gemini 無料枠**（無償の API キー） | Google のサーバー。**入力・出力とも Google のプロダクト改善に利用される** | ¥0 | ❌ 不可（動作確認・デモデータ用） |
| **Claude**（Anthropic API） | Anthropic のサーバー | 有料 | 各社の利用規約・プライバシーポリシーを確認のうえ判断 |

**必ず守ること:**

- **Gemini API の無料枠では、送信した入力とその出力が Google のプロダクト改善（モデルの改善を含む）に利用されます。** これは有料枠（課金を有効にしたプロジェクト）では行われません。この違いは Google の公式ドキュメントで確認しています（2026年8月時点。ポリシーは変更されうるため定期的に確認してください）。
- したがって、**実在の利用者の個人情報を扱う運用では、① Ollama（完全ローカル・データが外に出ない）または ② Gemini 有料枠のいずれかを使ってください。**
- **Gemini 無料枠は、動作確認・研修・デモデータでの試用に限定します。** 実データを無料枠に流すことは、要配慮個人情報の第三者提供にあたりうる行為であり、本ガイドラインでは認めません。
- Claude（Anthropic API）を使う場合のデータの取り扱いは、Anthropic のプライバシーポリシー・利用規約を各自で確認してください。
- **AI の出力は、登録・判断の前に必ず人間（支援者）が確認してください。** ナラティブAI抽出は抽出結果の確認ステップを経てから登録される設計ですが、内容の正誤に責任を持つのは確認した支援者です。AI が原文にない情報を補って生成することがあるため、原文と突き合わせ、不明な項目は不明のまま残してください。緊急時の禁忌事項・連絡先の確認には、AI チャットではなく AI を経由しない緊急照会（クライアント詳細）を使ってください。

**AI を一切使わない運用も選べます。**
台帳（クライアント情報・禁忌事項・推奨ケア・キーパーソン・手帳/受給者証）、緊急照会、更新期限アラートといった中核機能は **LLM をまったく使わずに動作**します。API キーを一つも設定しなければ、データは 1 バイトも外部に出ません。まずこの状態で運用を始め、必要になった時点で Ollama または Gemini 有料枠を足す、という進め方を推奨します。

### 2.3 Gemini API（Google）への送信範囲

`GEMINI_API_KEY` が設定されている場合、以下が **Google のサーバー（Gemini API）** へ送信されます。未設定なら送信されず、該当機能はスキップされます（意味検索は結果が空になるだけで、システムは壊れません）。

| 機能 | 送信される内容 | 送信契機 |
|---|---|---|
| 意味検索用のベクトル生成 | 支援記録・禁忌事項・推奨ケアのテキスト、Client 概要テキスト（**実名・生年月日は除外**、displayCode/血液型/障害名/禁忌/ケア/直近記録を含む） | 登録時に**自動**、および `scripts/backfill_embeddings.py` 実行時 |
| 意味検索（記録を探す） | 入力した検索キーワード | 「記録を探す」画面で意味検索を実行したとき |
| ~~音声の文字起こし~~ | — | **廃止しました（2026-08-12）** |
| AIチャット・ナラティブ抽出 | 入力した文章・面談テキスト | チャット／インテーク画面で Gemini を選んでいるとき |

- Client 概要テキスト（`lib/embedding.py::build_client_summary_text`）からは**実名・生年月日を除外**し、非識別の displayCode/clientId で代替しています（P0-5 対応）。ただし障害名・禁忌事項・ケア指示・直近の支援状況は類似度分析のため送信される点に留意してください。
- 要配慮個人情報を外部送信したくない場合は `GEMINI_API_KEY` を未設定にするか、Ollama に切り替えてください（中核の照会・登録・ブリーフィングは動作します）。

### 2.4 外部への通知連携（現時点では未搭載）

**現在の Web画面スタックには、LINE 等の外部サービスへ通知を送る機能は含まれていません。** 緊急照会はすべてローカルの Neo4j 内で完結します。

将来、外部メッセージングサービス（LINE Messaging API 等）と連携する場合は、送信内容がその事業者のサーバーを経由することになるため、以下を必ず守ってください。

**対策:**
- 通知に含める情報は必要最小限（識別子と緊急レベル程度）にとどめ、実名や病名を載せない
- 通知先グループのメンバー管理を適切に行い、退職者の即時除外を徹底する

## 3. 仮名化機能の運用

### 3.1 仮名化とは

仮名化（Pseudonymization）とは、個人を直接特定できる情報（氏名、生年月日、電話番号等）を、識別記号や部分マスクに置き換える処理です。本システムでは、**表示時のみ**仮名化を行い、データベース内の実データは変更しません。

### 3.2 仮名化モード

| モード | 説明 | 用途 |
|--------|------|------|
| `off` | 仮名化なし | 通常の業務運用 |
| `mask` | 部分マスク（山田→山●●●） | 研修、説明会、デモ |
| `pseudonym` | 架空名に置換（山田→青山あおい） | テスト、開発、公開資料 |

### 3.3 仮名化の対象フィールド

| フィールド種別 | mask モード例 | pseudonym モード例 |
|--------------|-------------|-------------------|
| 人名 | 山●●● | 青山あおい |
| 電話番号 | 090-\*\*\*\*-5678 | 090-0000-0001 |
| 生年月日 | 1995-XX-XX | 1995-07-22 |
| 住所 | 東京都●●区●●● | ○○県桜ヶ丘1-1-1 |
| 医療機関名 | ●●病院 | さくら病院 |
| 組織名 | ●●事業所 | あさひ福祉協議会 |

### 3.4 仮名化の有効化手順

```bash
# 1. .env に設定
PSEUDONYMIZATION_ENABLED=true
PSEUDONYMIZATION_MODE=mask          # または pseudonym
PSEUDONYMIZATION_SEED=any-string    # セッション固定シード

# 2. サービス再起動
docker compose restart
```

> **適用範囲**: 仮名化は Python 側の処理経路（`lib/pseudonymizer.py` を通る出力）で有効になります。Web画面から見える表示すべてに自動適用されるわけではないため、研修・説明会では**デモデータの使用（6.1）を第一選択**にしてください。

### 3.5 仮名化の安全上の例外

以下の情報は、**安全に直結するため仮名化の対象外**です:

- **NgAction（禁忌事項）**: リスクレベル、行為内容、理由
- **CarePreference（推奨ケア）**: ケアの指示内容
- **Certificate（手帳情報）**: 種類、等級（氏名は仮名化対象）

これは、緊急時に正確な禁忌情報やケア情報にアクセスできることが、利用者の安全を守るために不可欠だからです。

## 4. アクセス管理

### 4.1 物理的アクセス管理

本システムはローカル環境で動作するため、パソコンへの物理的アクセス管理が重要です。

- パソコンのログインパスワードを適切に設定する
- 離席時は画面ロックを徹底する
- パソコンを共有する場合は、OS のユーザーアカウントを分離する

### 4.2 Neo4j データベースへのアクセス

デフォルトのパスワード（`password`）は本番運用前に必ず変更してください。

```bash
# docker-compose.yml の環境変数を変更
NEO4J_AUTH=neo4j/your_strong_password
```

### 4.3 ネットワークアクセス

Neo4j はデフォルトで `localhost` のみリッスンします。同一ネットワーク内の他のパソコンからアクセスする場合は、ファイアウォール設定とアクセス制御を適切に行ってください。

## 5. バックアップと廃棄

### 5.1 バックアップ

```bash
# 定期バックアップ（推奨: 週次）
docker compose stop
cp -r neo4j_data neo4j_data_backup_$(date +%Y%m%d)
docker compose start
```

バックアップデータにも個人情報が含まれます。暗号化したUSBや施錠できる場所に保管してください。

### 5.2 データの廃棄

利用者が退所・転出した場合や、保存期間を超過した場合のデータ廃棄:

```cypher
// 特定クライアントのデータを完全削除
// Neo4j Browser（http://localhost:7474 / neo4j・password）で実行する
// ※ この操作は取り消せません。実行前に必ずバックアップを取ること
MATCH (c:Client {name: "氏名"})-[r]->(n)
DETACH DELETE c, n
```

廃棄の記録は監査ログ（AuditLog）に自動記録されます。

## 6. 研修・説明会でのデモ

### 6.1 デモデータの使用（推奨）

研修や説明会では、実際の個人情報を使わず、デモデータを使用してください。

```bash
# デモデータの投入
./installer/load-demo-data.sh

# デモ終了後にデモデータを削除
./installer/load-demo-data.sh --remove
```

デモデータは `isDemo = true` フラグが付与されており、実データと区別できます。

### 6.2 仮名化モードでの実データ使用

デモデータでは不十分な場合（実際の業務フローを見せたい場合）は、仮名化モードを有効にして実データを使用できます。

```
# .env を一時的に変更
PSEUDONYMIZATION_ENABLED=true
PSEUDONYMIZATION_MODE=mask
```

研修終了後は `PSEUDONYMIZATION_ENABLED=false` に戻してください。

## 7. インシデント対応

### 7.1 個人情報漏えい時の対応

1. **即座にアクセスを遮断**: Docker コンテナを停止 (`docker compose stop`)
2. **影響範囲の確認**: 監査ログ（AuditLog）で操作履歴を確認
3. **関係者への報告**: 管理者、個人情報保護責任者に報告
4. **原因の特定と再発防止**: パスワード変更、アクセス権限の見直し
5. **本人への通知**: 個人情報保護法に基づき、本人に通知

### 7.2 監査ログの活用

本システムは全ての操作を AuditLog ノードに記録しています。直近の操作履歴は Web画面のダッシュボードに表示されます。特定の利用者に絞って追う場合は、Neo4j Browser（http://localhost:7474）で次のように確認してください。

```cypher
// 特定クライアントに関する操作履歴
MATCH (a:AuditLog)-[:AUDIT_FOR]->(c:Client {name: "氏名"})
RETURN a.createdAt, a.action, a.details
ORDER BY a.createdAt DESC
```

## 8. 法的根拠

### 8.1 関連法令

- **個人情報の保護に関する法律**（個人情報保護法）
- **障害者の日常生活及び社会生活を総合的に支援するための法律**（障害者総合支援法）
- **社会福祉法**

### 8.2 要配慮個人情報

本システムが扱う以下の情報は「要配慮個人情報」に該当します:

- 障害の種類・等級
- 医療情報（かかりつけ医、処方薬等）
- 精神疾患に関する情報
- 生育歴・生活歴

要配慮個人情報の取得には、原則として**本人の同意**が必要です（個人情報保護法第20条第2項）。ただし、障害福祉サービスの提供に必要な場合は、法令に基づく例外が適用される場合があります。

### 8.3 第三者提供

本システムのデータを他の事業所や機関に提供する場合は、原則として本人の同意が必要です。ただし、以下の場合は例外:

- 法令に基づく場合（虐待通報等）
- 人の生命・身体の保護に必要な場合
- 公衆衛生の向上に必要な場合

## 付録: AI 提供各社のデータ取り扱い（確認先）

AI 機能を有効にする前に、選んだ提供元の最新の規約を必ず確認してください。ポリシーは変更されうるため、年 1 回程度の再確認を推奨します。

| 提供元 | 確認先 | 本ガイドラインでの扱い（2026年8月時点） |
|---|---|---|
| Ollama（ローカル） | — | データが外部に出ないため、確認不要 |
| Google（Gemini API） | https://ai.google.dev/gemini-api/terms | **無料枠は入力・出力がプロダクト改善に利用される**／有料枠は利用されない |
| Anthropic（Claude API） | https://www.anthropic.com/privacy | 利用規約・プライバシーポリシーを確認のうえ判断 |

判断に迷う場合は、**AI 機能を使わない**（API キーを設定しない）運用から始めてください。台帳・緊急照会・期限アラートはそれで問題なく動きます。
