# 発展的運用ガイド

基本操作（記録・照会）に慣れたあと、AIチャットや可視化を活用するためのガイドです。セットアップは [QUICK_START.md](./QUICK_START.md) を参照してください。

---

## アーキテクチャ概要

| レイヤー | ツール | 役割 |
|:--|:--|:--|
| **Next.js フロントエンド** | ブラウザUI（port 3001） | ダッシュボード・記録・検索・可視化・チャット |
| **FastAPI バックエンド** | API（port 8001） | REST + WebSocket + エージェント（照会・分析・レポート） |
| **Neo4j** | グラフDB（Docker, port 7687） | すべての支援データの保存先 |

AI（LLM）は Ollama / Gemini / Claude の選択制で、「LLM設定」画面と `.env` で切り替えます。**AI未設定でも中核機能（台帳・緊急照会・期限アラート・ブリーフィング）は動作します。**

---

## AIチャットの活用（要 LLM 設定）

「AIチャット」ページでは、データベースの内容について自然な日本語で質問できます。

**照会・分析:**
```
山田健太さんのプロフィールを表示して
```
```
更新期限が近い証明書を全クライアント分チェックして
```
```
佐藤さんの最近の支援記録を分析して、効果的だったケアパターンを教えて
```

**緊急時（禁忌→推奨ケア→連絡先の順で返ります）:**
```
田中さんがパニックを起こしています。緊急対応情報をください。
```

> 緊急照会はAIを経由しないDB直接検索でも提供されます（クライアント詳細の緊急照会。AI未設定でも使えます）。急ぐときはそちらが確実です。

**LLMの切り替え:** チャット中に「gemma4を使って」「claudeに切り替えて」と入力すると動的に切り替わります。セッション履歴は保持されます。

## 事業所検索（ServiceProvider）

WAM NET 由来の事業所データを取り込んでいる場合、チャットで検索できます:

```
北九州市の生活介護事業所で空きのあるところを探して
```
```
山田さんの就労B型の代替事業所を探して。現在の事業所が閉鎖予定のため。
```

口コミは ◎○△× の4段階で登録・参照できます。

## エコマップ（支援関係の可視化）

「エコマップ」ページから GUI で生成・ダウンロードできます（draw.io 形式。draw.io アプリで自由に編集可能）。

**4つのテンプレート:**

| テンプレート | 用途 |
|-------------|------|
| `full_view` | 包括的な全体像（初回面談時） |
| `support_meeting` | サービス担当者会議用 |
| `emergency` | 緊急時体制（Safety First） |
| `handover` | 引き継ぎ用（履歴含む) |

「知識グラフ」ページでは、データベース全体のつながりをそのまま探索できます。

## 意味検索（記録を探す・要 Gemini 設定）

「記録を探す」ページは、まったく同じ言葉が使われていなくても**意味の近い記録**を探し出します（例:「大きな声」で「叫んでいた」の記録もヒット）。支援記録・ケア指示・禁忌事項・クライアント概要から検索範囲を選べます。

キーワードの完全一致で探したい場合は、各クライアント詳細ページの記録一覧を使ってください。

## Ollama（ローカルLLM）の活用

オフライン環境・APIキー不要・**データがPCの外に出ない**運用に適しています。個人情報を扱う本運用の推奨構成です。

```bash
# 環境変数で初期プロバイダーを指定
export CHAT_PROVIDER=ollama
export OLLAMA_MODEL=gemma4:26b
```

> Gemini を使う場合の無料枠の条件（入力データがプロダクト改善に利用される等）は [manuals/PRIVACY_GUIDELINES.md](./manuals/PRIVACY_GUIDELINES.md) を確認してください。

## 音声対話型インテーク

「インテーク」ページで、音声対話による7本柱インテークが可能です。

- Web Speech API による音声認識
- WebSocket によるリアルタイムストリーミング応答
- エージェントが7本柱に沿って対話的に情報を収集

## バックエンドのエージェント構成（開発者向け）

`agents/` には照会・分析を担う agno エージェント（ケア改善提案・エコマップ生成・親の機能移行分析・レポート生成など）が、`skills/` には運用プロトコル・ワークフロー文書が含まれます。ルーティングの設計は `agents/ROUTING.md` を参照してください。

スキーマの正典は `docs/SCHEMA_CONVENTION.md` / `docs/SEMANTIC_MODEL.md`（shared-schema からの同期コピー・直接編集禁止）です。

## トラブルシューティング

### 画面（localhost:3001）が開かない

```bash
./scripts/doctor.sh              # 一括診断
```

`start.command`（Mac）/ `start.bat`（Windows）を再実行してください。

### Neo4j に接続できない

```bash
docker ps | grep neo4j
docker logs oya-inai-db-neo4j
docker compose restart neo4j
```

### Cypher クエリを直接確認したい

1. Neo4j Browser (http://localhost:7474) で直接クエリを実行（認証: neo4j / password）
2. スキーマ（ラベル・リレーション・プロパティ名）は `docs/SCHEMA_CONVENTION.md` と一致しているか確認
