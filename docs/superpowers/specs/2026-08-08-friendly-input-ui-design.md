# 「やさしい入力」パターン — 入力系ページUI改修 設計書

- 日付: 2026-08-08
- 承認: 河原さん（会話上で承認済み）
- 背景: PC操作に不慣れな福祉職員には、現状の入力系ページ（素のfile input・
  小さなselect・理由なきdisabledボタン・英語ステータス）は操作手順が分からない。

## 目的と成功条件

**成功条件: 初見の職員が手順書なしで「面談記録の音声アップロード」を完了できる。**

対象デバイスはPC中心。ただし文字・ボタンは大きめにし、タブレットでも操作可能にする。

## スコープ

- 対象: 面談記録 / クイックログ / ナラティブ入力 / インテーク（入力系4ページ）
- 対象外: 閲覧系ページ（ダッシュボード・検索・エコマップ等）、field-ui、音声録音機能の新設

## 共通UI原則

1. 本文16px以上・ラベル太字。主要ボタンは高さ48px以上・全幅
2. 操作は上から下に番号順（①クライアント → ②内容 → ③実行）。
   次にやるべきステップが常に1つだけ強調される
3. 状態はすべて日本語の文章で説明する。`success` / `error` 等の英語バッジは廃止
4. 押せないボタンには「あと『◯◯』を選ぶと押せます」と不足項目を明示する

## 共通コンポーネント（`frontend/src/components/friendly/`）

| 部品 | 仕様 |
|---|---|
| `StepSection` | 番号丸付きセクション枠。`done`（✓緑）/ `active`（強調）/ `waiting`（淡色）の3状態 |
| `ClientPicker` | 大きなselect（高さ48px・文字18px）。0件時は「まだ利用者が登録されていません → クライアント一覧から登録」と案内 |
| `FileDropZone` | 大きな点線ドロップ枠。クリックでもドラッグ&ドロップでも選択可。選択後は「🎵 ファイル名（サイズ）✓」＋「選び直す」。対応形式は「スマホの録音アプリのファイルがそのまま使えます」と平易に補足 |
| `GuidedSubmitButton` | 全幅大ボタン。不足項目を日本語でヒント表示。処理中は「アップロード中…（数分かかることがあります）」 |
| `ResultBanner` | 成功=緑・失敗=赤の大きな帯。失敗時は次にすべき行動を1文添える |

## ページ適用

- **面談記録**: ①クライアント → ②音声ファイル（FileDropZone）→ ③タイトル・メモ
  （任意・折りたたみ）→ ④アップロード。LLM未設定時は「文字起こしにはLLM設定が
  必要です（音声の保存はできます）→ LLM設定へ」を事前表示（`/api/system/status` で判定）
- **クイックログ**: ①クライアント → ②内容（状況は任意）→ ③記録する
- **ナラティブ入力**: 既存の検証→プレビュー→登録フローを StepSection で番号付け
  （フロー自体は変えない）
- **インテーク**: チャット型のため構造は維持し、共通UI原則1・3のみ適用

## テスト

- 既存 e2e 3本（narrative / navigation / dashboard）が通ること
- meetings 用 e2e を1本追加: クライアント未選択時にボタンへヒントが表示され、
  選択・ファイル指定で解除されること
